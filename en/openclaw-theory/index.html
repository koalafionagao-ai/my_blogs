Keyword 1: Restraint

My philosophy in all of this was: if I don't need it, it won't be built. And I don't need a lot of things.

Then just talk to pi. By default, pi gives the model four tools: read, write, edit, and bash. The model uses these to fulfill your requests. Add capabilities via skills, prompt templates, extensions, or pi packages.

As it turns out, these four tools are all you need for an effective coding agent. Models know how to use bash and have been trained on the read, write, and edit tools with similar input schemas.

pi's system prompt and tool definitions together come in below 1000 tokens.

Keyword 3: Experience

Many unified LLM APIs completely ignore providing a way to abort requests.
pi-ai was designed from the beginning to support aborts throughout the entire pipeline, including tool calls.

┌───────────────────────────────────────────┐
│          **User Interface (UI)**          │
│  - Input request (generate story)         │
│  - Display generated content & abort tips │
│  - "Abort" button / "Continue" button     │
└────────────────┬──────────────────────────┘
                 │ User Ops: Start / Abort / Continue
                 ▼
┌───────────────────────────────────────────┐
│   **App & Business Orchestration Layer**  │
│        **(pi-coding-agent)**              │
│  - Manage session & project context       │
│  - Inject tools / configure context       │
│  - Listen for abort signal                │
│  - If continue → Re-inject context        │
└────────────────┬──────────────────────────┘
                 │ Instructions + Context (includes partial content)
                 ▼
┌───────────────────────────────────────────┐
│          **Agent Core Layer**             │
│         **(pi-agent-core)**               │
│  - Start loop generation process          │
│  - Call LLM / execute tools               │
│  - Listen for AbortController signal      │
│      └── If triggered → Stop generation   │
│  - Collect generated partial content      │
│  - If continue → Resume from partial content
└────────────────┬──────────────────────────┘
                 │ Generated content / status return
                 ▼
┌───────────────────────────────────────────┐
│    **LLM Comm & Execution Layer**         │
│            **(pi-ai)**                    │
│  - Receive generation request             │
│  - Stream output text                     │
│  - Stop output on Abort signal            │
│  - Return partial content + stopReason    │
│  - If continue → Receive resume request   │
└───────────────────────────────────────────┘

**💡 Flow Highlights:**
- **When aborting:** Abort → Agent stops → Save partial content → UI prompt.
- **When resuming:** UI triggers "Continue" → Inject partial content → Agent resumes → LLM outputs.
- **Final content for user:** Complete text (Pre-abort + Post-resume).
- **Clear layer duties:** UI handles interaction, App layer manages context, Agent controls the loop, and LLM executes text generation.

Security Concerns: Benchmarking vs. Manus

Product PhasesInterface FeaturesSecurity IssuesStrategies
ChatBot
2022-2023		Text dialog box

(No web search, no Function Call yet)		Model has a "Brain":
Direct Prompt Injection
Jailbreak
• Mainly attacks the dialog box
• Outputs harmful speech, writes malicious code text
• But lacks physical destructive power.		Model: Fine-tuning and alignment (RLHF), "Ad-hoc Filtering"
Ports: Security auditing and rule interception for input and output
Copilot
2024-2025		RAG Retrieval-Augmented Generation

(Reading PDFs, summarizing webpages, querying databases, etc.)		Model grew "Eyes":
Indirect & Zero-Click Injection
• Malicious instructions embedded in external content
• Attackers inject harmful prompts into databases or knowledge bases the AI frequently visits
• Traditional filters fail because legal content and malicious instructions are mixed
• When AI reads data, it hits a hidden command and is instantly "flipped”.		"Input Sanitization"
"Data Loss Prevention (DLP)"
• Restrict AI access to sensitive databases (Principle of Least Privilege)
• Or perform manual desensitization before AI returns results.
Agent
2025-till now（2026）

→This is where OpenClaw stands today.		Cross-app scheduling and local code execution capability

(Reading local files, operating terminal CLI, deleting/writing emails, modifying code, etc.)		Model grew "Hands and Feet":
• Semantic privilege escalation
• RCE (Remote Code Execution)
• Promptware
• Security threats officially upgrade from "text pollution" to "system-level control takeover".		"Letting the LLM do security reviews itself" → Nested defense is useless .
Security deployment shifts fully toward "Architectural-level hard isolation" .
• Sandboxing: Locking the Agent in a cloud container or local restricted Docker .
• Plugin supply chain review: Real-time monitoring for ToxicSkills in the Agent tool library .
• Human-in-the-loop (HITL): Forcing a cut to the Agent's silent write permissions; any system call must have a human click to authorize.
